A8Database schema template

create table public.hosted_models (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  model text not null, tag text not null, plan text not null,
  status text not null default 'provisioning',
  created_at timestamptz default now(), unique (user_id, model, tag));
alter table public.hosted_models enable row level security;
create policy own on public.hosted_models for all using (auth.uid() = user_id);

Every new table: primary key, owner column, RLS on, an owner-only policy, indexes for its main query, and a retention note.

A14Customer support SOP

  1. Intake: support email or in-app form → ticket with plan, run id, model.
  2. Categorise: account/keys · run failure · model quality · billing · other.
  3. Respond within SLA (Business 4 business hours, Starter/Pro 1 business day, Free best effort).
  4. Resolve: known fixes in the help centre. Run failures follow the triage SOP (§2.4). Quality issues are routed to Fix/Testify.
  5. Escalate: to the CTO if it's a platform bug (S1/S2 opens an incident), to the CEO if it's a commercial dispute.
  6. Close: confirm with the customer, send CSAT, tag the root cause. Review tags weekly.

A15Incident response checklist

  • Declare: severity (§6.5), incident lead, channel, start time
  • Contain: revoke or rotate affected keys, disable the feature by flag, block abusive accounts
  • Assess: what data or users are affected and since when (audit logs)
  • Communicate: status page, affected users. For personal-data breaches, counsel advises on DPDP notification.
  • Recover: fix, verify, monitor for 24 h
  • Review within 5 days: blameless post-mortem, actions with owners and dates
