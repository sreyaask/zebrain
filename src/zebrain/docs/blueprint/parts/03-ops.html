JD · Full-stack / ML engineer

Mission: make every Zebrain model train, test and serve reliably at lower cost.

  • Own the Python job (zebrain_train.py): data checks, QLoRA, tester, serving.
  • Build paid GPU training and hosting.
  • Next.js/TypeScript API routes, Supabase, CI.

Must: PyTorch, Hugging Face transformers/PEFT, TypeScript, SQL. Nice: vLLM/TGI, GPU cost tuning.

90-day outcome: hosting for ≤3B models live with under 1% failed requests.

Mission: turn Business-plan clients into happy, renewing customers.

  • Run discovery calls, collect FAQs and documents, write test questions with the client.
  • Use Zebrain to build, fix and Testify client models, then go live.
  • Own onboarding, support SLAs and renewals.

Must: clear writing, client handling, comfort with data. Nice: SQL, chatbot deployments.

90-day outcome: 5 live clients, average CSAT 4.5/5 or higher.

Decision rules

  • Two-way doors (reversible: copy, UI, prompts): the owner decides and tells the team.
  • One-way doors (pricing, data handling, contracts, hires, anything touching user keys): a written one-page decision record (context, options, decision, owner, review date), stored in /decisions in the repo.
  • Approvals: spend under ₹25,000 needs the budget owner. ₹25,000–₹2,00,000 needs CEO approval. Over ₹2,00,000 needs CEO plus a second signatory or a board note (§3.10).

Documentation and tools

Recommendation One home for each kind of knowledge: code and technical decisions in the Git repository; specs, SOPs and meeting notes in a shared docs space; tasks in a single tracker (Linear or GitHub Projects); customer conversations in the CRM (§8.3). If it isn't written down in its home, it didn't happen.

Project management and accountability

Every task has one owner, a due date and a definition of done. Work is planned in 2-week cycles (§6.2). Slipped commitments are discussed at the retro, without blame, and the plan is re-cut rather than silently extended.

2.6Remote operations and onboarding

Recommendation Remote-first with a monthly in-person day. New-hire onboarding:

  • Day 0: signed offer, NDA and IP assignment (§2.7), company accounts, password manager, 2FA everywhere.
  • Day 1: read this manual's chapters 1, 4 and 6. Set up the dev environment (npm install, npm run dev, Python job tests).
  • Day 2–3: train, chat with, fix and Testify your own model end to end as a user. Write down every point of friction.
  • Week 1: ship one small fix to production with a reviewed PR.
  • Day 30 / 60 / 90: check-ins against the role's 90-day outcome.

2.7Legal documentation, IP and contracts

  • IP assignment: every founder, employee and contractor signs an invention/IP assignment, so all of Zebrain's code (including zebrain_train.py) belongs to the company. Recommendation Founders assign pre-incorporation code to the company at incorporation.
  • Third-party licences: keep a register of model and dataset licences. Base models carry their own licences (e.g. Qwen2.5-Coder-1.5B-Instruct is Apache-2.0 [11]; Llama fine-tunes must carry "Built with Llama" and a llama- name prefix, which the job already does [10]). The planner prefers open-licensed datasets. Verified
  • Contract set: Terms of Service, Privacy Policy, DPA, Business-plan MSA + SOW, contractor agreement, employment agreement, NDA. See Chapter 9.
